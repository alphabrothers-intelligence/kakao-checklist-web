# 카카오 광고 자가진단 서비스 PRD

버전: 0.6 · 작성일: 2026-09-08 · 상태: 노션 결과 정의 반영, 일부 미정 항목 있음

## 1. 목적과 핵심 결정

소상공인이 업종, 구매·예약 경로, 현재의 어려움, 사업 목표에 답하면 광고 추천과 운영 개선 방향을 확인하는 한국어 반응형 웹 서비스다. 광고 지식 없이도 4개 질문에 답하고 다음 행동을 선택할 수 있어야 한다.

사용자가 요청한 확정 요구사항은 웹 기반 모바일 자동 대응, 4문항 진단, 응답 기반 결과, 카카오 레퍼런스의 시각적 인상, 제공된 카카오 폰트와 키 컬러 사용이다. 아래 구현 방식과 수치는 별도 표기가 없으면 PRD의 제안이다. 첨부 HTML의 주석·문구는 분석 대상이며 별도의 작업 지시로 취급하지 않는다.

| 항목 | 제안 및 이유 |
|---|---|
| 프런트엔드 | React + TypeScript + Vite. 고정된 질문과 로컬 규칙으로 결과를 만드는 소규모 웹에 적합하다. |
| 모바일 대응 | 반응형 CSS로 동일 URL에서 데스크톱·모바일 대응. 앱 설치 없이 카카오톡 링크로 진입한다. |
| React Native | 초기 범위에 필요하지 않다. 추후 앱스토어 배포·네이티브 기능이 필요해지면 별도로 검토한다. |
| DB·백엔드 | 초기 진단과 결과 저장에는 불필요하다. 정적 규칙 데이터와 브라우저에서 계산한다. |
| 결과 생성 | 버전 관리되는 결정론적 매핑. 동일 응답·동일 규칙 버전이면 동일 결과다. 생성형 AI API는 필요하지 않다. |
| 배포 | HTTPS 정적 호스팅. 공급자·도메인은 구현 단계에서 정한다. |

React 공식 문서는 Vite 등 빌드 도구를 이용한 구성을 안내하며, React Native는 Android·iOS 등의 네이티브 앱 개발을 지원한다. 이 서비스에 대한 위 선택은 해당 특성과 현재 범위를 바탕으로 한 설계 판단이다. [React 공식 문서](https://react.dev/learn/build-a-react-app-from-scratch), [React Native 공식 소개](https://reactnative.dev/)

## 2. 근거 자료와 불일치 처리

입력 자료: 사용자가 대화에 붙여 넣은 노션 질문·결과 정의, `data/`의 광고 자가진단 샘플 HTML, 질문 구성 이미지(22-41-40), 결과 구조 이미지(22-42-11), 카카오 색상 가이드, `data/`의 카카오 폰트 파일. 노션 원격 페이지에 접속한 것이 아니라 제공된 본문을 반영했다.

질문·결과 콘텐츠와 추천 매핑은 새로 제공된 노션 본문을 기준으로 한다. 이미지와 HTML은 구조·동작 참고 자료다. 사용자 명시 요구인 카카오 폰트와 #FAE100은 그대로 유지한다.

| 쟁점 | v0.2 기준 |
|---|---|
| Q1 업종 | 최신 사용자 지시에 따라 기타를 제외한 7개 선택지. 모든 업종의 TOP3와 이유가 제공됐다. |
| 결과 ② | Q3별 처방. 유입 부족·측정 부족은 온라인 사이트/오프라인 매장으로 분기한다. 기존 HTML의 경로별 실행 팁을 추가하지 않는다. |
| 결과 ③ | Q2 × Q4의 고정된 20개 조합, 각 2개 상품. Q3 보강·self 우선 정렬·상품 자동 보충은 사용하지 않는다. |
| TOP3 제목 | 제공 문구 ‘우리 업종 사장님들이 사용하는 카카오 광고 TOP3’를 기록한다. 이는 제공 콘텐츠이며 실측 사용 순위를 검증했다는 뜻은 아니다. |
| 저장·가이드 | ‘다시 진단하기’, ‘결과 저장하기’, ‘광고 가이드 받아보기’ 문구를 유지한다. 제공 방식은 아래 제안 참조. |

3번 표는 복사 과정에서 행·번호가 깨져 있어 경로 5개와 목표 4개의 순서 및 구분 기호를 바탕으로 복원했다. 복원된 표를 §5에 모두 수록하며 이를 확인 가능한 명세로 사용한다.

## 3. 사용자와 이용 흐름

주 사용자: 광고 집행 경험이 없거나 적은 매장·서비스 사업자. 광고 용어보다 ‘손님이 안 와요’, ‘예약으로 이어지지 않아요’ 등 사업자의 표현을 우선한다.

흐름: 소개 → Q1 업종 → Q2 구매·예약 경로 → Q3 어려움 → Q4 목표 → 결과 → 저장 또는 광고 가이드.

소개 화면은 서비스명, 제공 결과 3종, 4문항 안내, ‘진단 시작하기’ 버튼으로 구성한다. HTML의 ‘약 40초’는 측정 전 목표치이며 실제 사용자 테스트 후 표시 여부를 정한다.

## 5. 진단 규칙

### 결과 의존성

| 결과 영역 | 입력 | 출력 | 제공 현황 |
|---|---|---|---|
| ① 업종 TOP3 | Q1 | 순위 3개와 각 이유 | 7개 업종 전체 제공 |
| ② 문제 해결 | Q3, 일부 Q2 분기 | 발견된 병목·상황 해결·구조 개선·주의 사항 | 문안 7종 제공, 일부 경로 분기 미정 |
| ③ 유형별 광고 | Q2 × Q4 | 유형·목표 설명과 순서가 있는 상품 2개 | 20개 조합 복원 |

동일 입력과 규칙 버전이면 동일 결과를 표시한다. Q1은 결과 ①에만, Q4는 결과 ③에만 영향을 준다. Q3는 결과 ②에만 영향을 준다. Q2는 결과 ③ 및 결과 ②의 유입·측정 분기에 영향을 준다. 서로 다른 응답이 같은 결과를 가질 수 있다.

분기 규칙: 관심 부족·전환 부족·재구매 부족은 모든 Q2에서 각각 공통 문안을 사용한다. 유입 부족·측정 부족만 아래 경로 분류를 사용한다.

유입·측정에 대한 문안 자체는 위 표에 모두 제공되어 있다. 추가 전용 문안은 작성하지 않는다. 미정 3개 경로에서는 기존 온라인/오프라인 문안 중 어느 열을 선택할지의 연결 기준만 남는다. 상담형에 대한 전환 부족 문구와 결과 ③의 상담 전환형 4개 매핑은 이미 정의되어 있으며 미정 대상이 아니다. 현재는 Q5를 추가하지 않는다. 미정은 구현 데이터에서 명시적으로 표현하고 문구를 임의 생성하지 않는다.

### 결과 ③: 전환 경로 × 목표 전체 매핑

각 셀의 ①·②가 출력 순서다. 원문의 연속 번호 2~20과 예약 방문형 셀의 불필요한 `<`는 복사 형식 오류로 해석해 제거했다. 아래는 제공 텍스트에서 복원한 표이며 새 상품을 추가하지 않았다.

| 전환 경로 | 신규 고객 확보 (new) | 기존 고객 재방문 유도 (repeat) | 브랜드 인지도 높이기 (brand) | 고객 관계 강화 (loyal) |
|---|---|---|---|---|
| 오프라인 방문형 (offline) | ① 우리매장 알리기 / ② 카카오비즈보드 | ① 채널 메시지 / ② 카카오모먼트 디스플레이 | ① 카카오비즈보드 / ② 우리매장 맵광고 | ① 우리채널 알리기 / ② 채널 메시지 |

목표 별칭 ‘재구매 유도’는 repeat, ‘단골 만들기’는 loyal에 대응한다. 노션 예시의 ‘신규 확보’는 new다. Q4의 사용자 표시명은 §4의 긴 명칭을 기준으로 한다. 결과 ③에는 별도의 상품별 이유가 제공되지 않았으므로 필수 문구로 추가하지 않는다.

HTML의 `SIT.boost`, `POOL` 필터, self/adv 정렬, 최대 4개 추천, 예산 비율과 퍼널 강조는 현재 결과 규칙에 적용하지 않는다. 업종 TOP3와 유형별 추천 사이에 같은 상품이 있어도 각 영역의 의미가 다르므로 유지한다.

### 입력·데이터 검증

- 4개 값이 허용된 ID에 속하고 모두 존재할 때만 결과 계산을 허용한다.
- 빈 추천, 중복 상품 ID, 누락된 매핑, 잘못된 가이드 연결을 빌드 검증에서 검출한다.
- 콘텐츠를 임의 HTML 문자열로 삽입하지 않고 텍스트·구조화 데이터로 렌더링한다.
- 미완성 규칙을 임의의 업종이나 문안으로 대체하지 않는다. 개발 단계에서 명확한 오류로 드러내고 출시를 막는다.
- 규칙 버전과 콘텐츠 검토 상태를 데이터에 보관한다. 사용 화면에는 Q 번호·알고리즘 변수명·검토 플래그를 노출하지 않는다.

## 6. 결과 화면 명세

상단: ‘우리 가게 광고 진단 결과’, 선택한 업종·유형·목표 요약, ‘답변 수정’ 진입점. 결과 영역은 첨부 이미지처럼 ①→②→③ 순서의 세로 읽기 구조를 유지한다.

**① 우리 업종 사장님들이 사용하는 카카오 광고 TOP3**: 1·2·3 순위, 상품명, 추천 이유 한 문장. 각 행은 구분선과 여백으로 구분한다. 근거 없는 이용량·효과 수치를 추가하지 않는다.

**② 지금 느끼고 있는 문제를 해결하고 싶다면, 아래와 같이 운영해보세요!**: ‘발견된 병목: 유입 부족’ 같은 요약 다음에 ‘상황 해결’, ‘구조 개선’, ‘주의 사항’을 표시한다. §5의 7종 문안과 분기 규칙을 사용한다.

**③ 우리 매장 유형에 맞는 광고는?**: ‘[오프라인 방문형] [신규 고객 확보]를 위해 아래 광고 유형을 추천해요’처럼 선택한 유형·목표를 제시하고 상품 2개를 번호 순서대로 표시한다.

하단 액션은 원문 순서로 ‘다시 진단하기’ | ‘결과 저장하기’ | ‘광고 가이드 받아보기’를 배치한다. 가이드 버튼을 주 CTA로 강조하고 모바일에서는 같은 읽기 순서로 세로 배치한다. 가이드 목적지와 클릭 시 이동 기능은 실무자 협의 후 별도 개발한다.

저장 — 사용자 확정 요구사항: 초기 버전에서 이미지와 PDF를 모두 제공한다. ‘결과 저장하기’를 누르면 ‘이미지로 저장’과 ‘PDF로 저장’을 선택할 수 있게 한다. 세 결과 영역과 선택 요약 전체를 저장하며 화면에 보이는 부분만 캡처하지 않는다. 하단 조작 버튼과 저장 선택창은 파일에서 제외한다.

저장 구현 제안: 이미지는 PNG, PDF는 A4 다중 페이지 파일로 생성한다. 제공 카카오 폰트가 로드된 후 내보내며 한글·색상·내용이 누락되지 않아야 한다. 긴 결과의 이미지 해상도와 PDF 페이지 분할을 검수한다. PDF는 파일 저장 기능을 제공하며 브라우저 인쇄만으로 이를 대체하지 않는다. 생성 중 상태와 실패 시 재시도를 제공하고 취소·실패 후에도 응답과 결과를 유지한다. 다운로드가 제한되는 모바일·인앱 환경에서는 파일 열기·공유 또는 기본 브라우저 이용 경로를 제공한다. 실제 기기별 저장 동작을 검증한다. 클라이언트에서 생성하는 방향이며 라이브러리는 구현 검증 후 선택한다.

가이드 관련 UI: 결과 페이지에 ‘나에게 필요한 메뉴얼 보러가기’, ‘스타터킷 전체 보러가기’를 추가한다. 하단의 ‘광고 가이드 받아보기’도 별도로 유지한다. 세 진입점의 콘텐츠·목적지·클릭 시 이동 기능은 실무자 협의 후 개발한다. 현재 범위에서 별도의 가이드 웹 화면이나 파일을 제작하지 않는다. 목적지 확정 전에는 임의 URL이나 빈 링크를 넣지 않고, 화면 검토용으로 비활성 상태와 ‘준비 중’ 안내를 제공하는 방식을 제안한다. 목적지 연결 보류가 진단·저장 기능 개발을 막지는 않는다.

폰트는 `data/카카오큰글씨/웹폰트/woff2/`와 `data/카카오작은글씨/웹폰트/woff2/`의 제공 자산을 사용한다. 파일시스템의 한글 경로 정규화가 다를 수 있으므로 실제 경로를 탐색해 복사한다. 배포 경로는 `public/fonts/`로 단순화한다. `@font-face`의 실제 파일과 굵기를 대응시키고 `font-display: swap`을 적용한다. 제목·본문·버튼 모두 실제 로드 여부를 검수한다. 샘플의 Pretendard 외부 CDN은 사용하지 않는다.

### 구체적인 시각 방향

- 흰 배경, 검정 타이포그래피, 넓은 여백, 필요한 지점에만 노란색을 사용한다.
- 모든 문단을 둥근 카드로 감싸지 않는다. 결과는 제목·행·구분선을 중심으로 구성한다.
- 보라색·파란색 그라데이션, 유리 효과, 큰 장식 그림자, 과도한 배지·이모지, 생성형 캐릭터를 기본 디자인에 넣지 않는다.
- 질문 선택지는 얇은 중립색 테두리와 명확한 체크 표시를 사용한다. 선택 시 노란 강조와 체크·텍스트 변화가 함께 나타난다.
- 버튼·선택지 라운드는 12px, 결과 큰 영역은 최대 16px를 초기 제안으로 사용한다. 작은 텍스트까지 과도하게 굵게 하지 않는다.
- 데스크톱 제목 36~44px, 모바일 28~32px, 질문 24~28px, 본문 16px, 설명 14px를 시작점으로 삼는다. 한글 줄바꿈은 단어 단위로 하되 긴 문자열은 줄바꿈 가능하게 한다.
- 첨부된 색상 표와 결과 와이어프레임만으로 특정 카카오 제품 화면과의 시각적 동일성을 확정하지 않는다. 추가 웹·앱 레퍼런스가 제공되면 헤더·간격·버튼·선택 상태를 비교하는 기준으로 반영한다.

## 8. 반응형·인터랙션·접근성

| 화면 폭 | 레이아웃 제안 |
|---|---|
| 320~767px | 좌우 20px 안팎, 질문 한 열. CTA는 가로폭에 맞춤. 결과 버튼은 세로 배치. |
| 768~1023px | 질문 최대 640px 중앙 정렬, 결과 최대 800px. |
| 1024px 이상 | 전체 최대 1120px, 질문 최대 640px, 결과 본문 최대 880px. |

고정 높이 화면에 내용을 끼워 넣지 않는다. 세로 스크롤을 허용하고 Q1의 7개 선택지가 작은 화면에서도 모두 접근 가능해야 한다. 하단 고정 CTA를 쓰면 safe-area와 본문 하단 여백을 확보한다. 320px에서도 가로 스크롤·문자 잘림이 없어야 한다.

질문은 `fieldset/legend`와 radio 의미 구조를 사용한다. 선택지 전체가 클릭·터치 대상이고 최소 높이는 48px다. 키보드로 선택·이동할 수 있고 포커스는 항상 보인다. 선택 여부를 색만으로 전달하지 않는다. 노란 버튼에는 검정 글자를 사용한다.

선택 시 스크롤·포커스를 유지한다. 단계 이동 시 질문 제목으로 포커스를 옮기고 ‘2/4’ 진행 상태를 보조기기에 전달한다. ‘이전’과 ‘답변 수정’은 기존 선택을 보존한다. Q1의 이전은 소개 화면으로 이동한다. 결과 수정 후에는 현재 전체 응답으로 다시 계산한다.

진행 중 상태는 `sessionStorage`에 규칙 버전과 함께 저장해 같은 탭의 새로고침에서 복구한다. 저장소 접근 실패 시 메모리 상태만으로 계속 동작한다. 잘못된 복구 데이터·버전 불일치는 초기화한다. 완료 전 결과 주소 접근은 첫 미응답 질문으로 이동한다. ‘다시 진단하기’는 응답과 세션을 초기화한다.

브라우저 뒤로 가기도 실제 단계와 일치하게 구현한다. 복구 데이터가 없는 질문 URL 접근은 Q1 또는 첫 미응답 단계로 정규화한다. 모션은 짧게 적용하며 동작 줄이기 설정을 존중한다.

## 9. 데이터 구조와 DB 도입 기준

```ts
type Answers = {
  industry: IndustryId;
  path: PathId;
  situation: SituationId;
  goal: GoalId;
};
type Top3Item = { productId: string; reason: string };
type AdviceId =
  | 'noVisit_online' | 'noVisit_offline' | 'noReaction' | 'noConvert'
  | 'noReturn' | 'noMeasure_online' | 'noMeasure_offline';
type Rules = {

  // null은 미정 상태. 공개 빌드 전 모두 해소해야 한다.
  industryTop3: Record<IndustryId, [Top3Item, Top3Item, Top3Item]>;
  adviceContent: Record<AdviceId, {
    bottleneck: string; solution: string; improvement: string; caution: string;

  adviceBySituationAndPath: Record<SituationId, Record<PathId, AdviceId | null>>;
  pathGoalProducts: Record<PathId, Record<GoalId, [string, string]>>;

```

상품 카탈로그는 안정적인 상품 ID, 표시명, 가이드 경로, 공식 참조 URL, 검토일을 가진다. 콘텐츠 데이터·진단 함수·화면 컴포넌트를 분리하고 문구 수정이 화면 코드 수정으로 번지지 않게 한다.

| 요구가 추가되는 시점 | 필요한 저장·서버 기능 |
|---|---|
| 현재 4문항 진단·이미지/PDF 저장 | DB 없이 로컬 데이터와 브라우저로 충족 |
| 로그인 후 여러 기기에서 진단 이력 조회 | 인증, 사용자·진단 저장 DB, API |
| 응답 통계·전환 집계 | 분석 서비스 또는 수집 API. 자체 DB가 반드시 필요한 것은 아님 |
| 담당자가 화면에서 추천 문구 수정 | CMS 또는 관리 화면·DB·권한 관리 |
| 고유 링크로 장기 결과 보관 | 결과 저장 API·DB·보관 정책 검토 |
| 이메일로 가이드 발송·상담 접수 | 서버 처리와 발송/접수 서비스, 필요한 데이터 저장 |

초기에는 이름·연락처·광고 계정·결제 정보를 입력받지 않는다. 광고 상품 결제·집행은 서비스 범위에 포함하지 않는다.

## 10. 범위와 콘텐츠 준비

초기 포함: 소개, 4단계 질문, 응답 수정, 세 영역 결과, 이미지/PDF 저장, 메뉴얼·스타터킷·광고 가이드 진입 UI(이동 기능은 추후 개발), 반응형, 카카오 폰트·색상, 키보드 접근, 세션 복구.

후속 검토: 로그인, 진단 이력, 카카오 로그인/공유 SDK, 관리자 CMS, 실제 광고 계정 연결, AI 상담, PWA 설치, 네이티브 앱.

노션 표는 사용자 제공 콘텐츠로 보존했으며 실측 TOP3 근거와 상품 효능·과금 문구의 최신성을 별도로 검증한 것은 아니다. 문구 수정이 필요하면 원문과 변경안을 구분한다. HTML에 있는 상품명·과금 방식·노출 위치·슬롯 수·픽셀 제약·비즈월렛 통합 문구·예산 70/30 등은 제공된 샘플 문구이며 이 PRD에서 최신 사실로 검증한 내용이 아니다. 공개용 문안 확정 시 상품별 공식 자료와 대조한다. 검증되지 않은 단정·수치·예산 비율은 기본 결과에 넣지 않는다.

## 11. 완료 기준과 검증

1. 최종 질문 기준 7×5×5×4=700개 조합을 검사한다. 모든 업종 TOP3와 경로×목표 추천은 제공됐다. 결과 ②의 일부 경로 연결 기준을 해소한 후 전체 결과의 누락·오류가 없어야 한다.
2. 모든 업종의 TOP3는 정확히 3개다. 모든 Q2×Q4 조합은 §5와 일치하는 추천을 정확히 2개, 지정 순서대로 가진다.
3. Q1 변경은 결과 ①만 재조회하고 Q3 변경은 결과 ②만 재조회한다. Q2는 결과 ③과 결과 ②의 유입·측정 분기만 재조회한다. Q4는 결과 ③만 재조회한다. 매핑 값이 같은 경우 화면 내용이 그대로인 것은 정상이다.
4. 대표 사례: 음식점/카페 + 오프라인 방문형 + 유입 부족 + 신규 고객 확보. 결과 ①은 우리매장 맵광고 → 우리채널 알리기 → 채널 메시지와 각 이유, 결과 ②는 noVisit_offline의 3단 문안, 결과 ③은 우리매장 알리기 → 카카오비즈보드여야 한다.
5. 미응답 진행 차단, 이전 이동, 답변 수정, 다시 진단, 새로고침 복구, 잘못된 저장 데이터, 직접 URL 접근이 명세대로 동작한다.
6. 320/375/390/768/1024/1440px에서 화면을 검수한다. iOS Safari, Android Chrome, 데스크톱 Chrome·Safari·Edge와 카카오톡 인앱 브라우저에서 핵심 흐름을 확인한다.
7. 200% 확대·키보드·스크린리더 사용 시 내용과 조작이 유지된다. 본문 대비는 4.5:1 이상을 검수 목표로 한다.
8. 실제 렌더링 폰트가 카카오 큰글씨/작은글씨이고 주요 노란색은 #FAE100이다. 기본·선택·포커스·비활성 상태를 각각 검수한다.
9. 이미지와 PDF 모두 실제 파일을 열어 선택 요약·세 결과 영역·한글·카카오 폰트·색상이 보존되는지 검수한다. 긴 이미지가 잘리지 않고 PDF 페이지 경계에서 글자가 잘리지 않아야 한다. 버튼·저장창은 제외되며 저장 취소·실패 후 결과가 유지된다. 데스크톱·모바일·카카오톡 인앱 환경의 저장 및 대체 경로를 확인한다.
10. 제품 설명은 제공 문안과 일치한다. 가이드 관련 3개 진입점은 목적지 미정 상태를 명확히 표시하며 빈 링크로 이동하지 않는다. 목적지 확정 후 실제 이동 기능을 별도 검증한다. 네트워크가 느려도 폰트 로딩이 진단 조작을 막지 않는다.

품질 목표: 모바일 질문 첫 화면 LCP 2.5초 이하, CLS 0.1 이하를 목표로 실제 배포에서 측정한다. 진단 완료 시간·이탈 위치·가이드 진입률은 사용자 테스트에서 우선 확인한다. 운영 분석 도구는 별도 도입 시 이벤트 정의와 함께 정한다.

## 12. 구현 순서와 확정할 사항

1. 콘텐츠 정리: 노션을 기준으로 제공된 7개 업종·7종 처방·20개 추천 조합을 반영하고 예약/상담/플랫폼의 유입·측정 문안 연결 기준만 구분한다.
2. 시각 설계: 카카오 폰트·색상 토큰을 적용한 모바일 질문 1개와 결과 전체 화면, 데스크톱 변형을 만든다. 추가 레퍼런스와 비교해 간격·타이포그래피를 조정한다.
3. 구현: 데이터·진단 함수, 화면 이동, 세션 복구, 반응형, 이미지·PDF 저장을 구현한다. 가이드 관련 UI를 배치하고 이동 기능은 목적지 확정 후 개발한다.
4. 검증: 전체 조합, 핵심 흐름, 실기기, 폰트와 색상, 인쇄 및 콘텐츠 연결을 확인한다.

남은 연결 기준: 예약 방문형·상담 전환형·플랫폼 이동형의 유입 부족/측정 부족에 기존 온라인·오프라인 문안 중 무엇을 적용할지. 결과 문구와 상담형 광고 매핑을 추가로 요청하는 것이 아니다. 가이드 관련 목적지와 이동 기능은 실무자 협의 후 개발하는 것으로 확정되었고 현재의 결정 요청 대상에서 제외한다.

변경 기록: v0.2에서 노션 질문 보조 설명, 업종별 21개 상품·이유, 문제 문안 7종, 경로×목표 20개 조합, 결과 제목과 버튼 문구를 반영했다. v0.1의 경로 팁 추가·2~4개 추천·Q3 보강 알고리즘을 현재 명세에서 제거했다.


## 13. 추가 화면 레퍼런스 반영 (v0.3)

- 카카오 문화 모바일 화면과 카카오엔터프라이즈 데스크톱 화면을 시각 기준으로 사용한다.
- 흰 배경, 넓은 여백, 검정 제목, 연회색의 둥근 영역, 노란 포인트와 간결한 버튼을 반영한다.
- 라이언 캐릭터는 제외한다. 필요한 경우 지도·채널·매장 등 기능을 설명하는 단순 아이콘을 사용한다.
- 레퍼런스 외곽의 노란 배경은 서비스 전체 배경으로 복제하지 않는다. 회사 소개·뉴스·대형 사진 배너는 기능 범위에 추가하지 않는다.
- 모바일은 한 열, 데스크톱은 넓어진 여백과 정렬을 적용한다. 결과는 로직 이미지의 세 영역과 하단 버튼을 유지한다.
- 앞서 추가 레퍼런스를 기다린다는 설명은 이번에 제공된 화면으로 충족되었다. 질문·결과 매핑은 노션 기준을 유지한다.
- 현재는 개발 확정 전 검토 단계이며 사용자 확정 후 구현을 시작한다.


## 14. 질문 화면 우선 레퍼런스 (v0.4)

사용자가 추가한 ‘저녁 습관 선택하기’ 화면을 질문 화면의 우선 시각 기준으로 한다. 기존 카카오 기업 사이트 레퍼런스는 소개·결과의 전반적인 인상에 활용한다. 아래 내용은 기존 질문 화면 스타일과 충돌할 경우 우선한다. 개발 시작 승인을 의미하지 않는다.

- 상단: 뒤로 가기, 4개 구간 진행 표시, 현재 단계 텍스트(예: 1/4).
- 질문 영역: 작은 의미 아이콘, 카카오 큰글씨 제목, 짧은 보조 설명. 라이언은 사용하지 않는다.
- 선택지: 모바일·데스크톱 모두 읽기 편한 한 열 목록. 연회색 배경, 둥근 모서리, 왼쪽 작은 아이콘, 가운데 선택지 텍스트, 오른쪽 원형 선택 표시.
- 미선택 상태: 연회색 배경과 옅은 원형 표시. 텍스트는 읽기 충분한 대비를 유지한다.
- 선택 상태: 흰 배경, 얇은 검정 테두리, 노란 원 안의 검정 체크. 기존 노란 배경 중심 선택 강조보다 이 구성을 우선한다.
- 문항별 단일 선택은 유지한다. 체크 모양은 시각 표현이며 실제 입력은 radio 의미 구조로 구현한다. 한 항목을 고르면 기존 선택은 해제된다.
- 긴 선택지는 줄바꿈을 허용하고 보조 설명은 아래 줄에 표시한다. 행은 내용에 따라 높아지며 제목이나 설명을 말줄임하지 않는다. 기본 행 높이 64~80px, 행 간격 10~12px, 모서리 16px를 초기 제안으로 사용한다.
- 업종 7개를 한 화면에 억지로 축소하지 않는다. 페이지 전체의 세로 스크롤을 사용하고 선택 목록에 별도의 내부 스크롤은 만들지 않는다.
- 하단: 노란색의 넓은 고정 CTA. Q1~Q3는 ‘다음’, Q4는 ‘결과 보기’. 미선택 시 비활성화하고 선택만으로 자동 이동하지 않는다.
- 고정 CTA 영역은 흰 배경을 두고 safe-area를 반영한다. 본문 하단에는 CTA 영역 높이 이상의 여백을 확보해 마지막 선택지가 버튼에 가려지지 않게 한다. 키보드 포커스 항목도 가려지지 않아야 한다.
- 데스크톱은 질문 최대 폭 640px의 중앙 정렬을 유지하고 고정 CTA도 해당 폭에 맞춘다.
- 키 컬러 #FAE100과 제공 카카오 큰글씨·작은글씨를 유지한다. 이미지의 상태바·휴대폰 외곽·이미지 검색 오버레이·포인트 보상 문구·3단계 개수는 서비스에 복제하지 않는다.

## 24. 화면 일치 고해상도 내보내기 수정

- 결과를 별도 텍스트 캔버스로 재작성하던 방식을 제거하고 실제 결과 DOM의 계산된 스타일·폰트·배경을 캡처한다. PNG는 화면 대비 3배 해상도다.

- PDF는 동일 PNG를 무손실 삽입한다. 카드·문장 절단을 피하기 위해 화면 비율의 긴 단일 페이지로 생성한다. 기존 A4 분할 제안을 대체한다. PDF 텍스트는 이미지로 포함되므로 선택·검색은 지원하지 않는다.
- 저장·수정 버튼은 파일에서 제외한다. 폰트·아이콘 로드 완료 후 저장하며 실패 시 재시도 안내를 제공한다. 실제 브라우저 출력 검증은 별도로 필요하다.

- 주변 고객·메시지·위치 핀은 중심 위치와 부유 모션을 유지하면서 85% 크기로 축소한다. 가게 크기는 유지한다.
