## 사용자 제공 표와의 재대조 (2026-09-09)

기존 700개 조합 검사는 결과의 누락·형태를 확인하는 검사였으며 모든 문구의 원문 일치를 보장하지 않았다. 이번에는 앱 데이터와 별도로 원문을 옮긴 `tests/fixtures/approved.mjs`를 기준으로 검사한다.

| 대상 | 대조 범위 |
|---|---|
| 질문 | 4개 질문, 7·5·5·4개 선택지 및 보조 설명 |
| 결과 ① | 7개 업종 × TOP3: 광고명, 순서, 추천 이유 21개 |
| 결과 ② | 7종 문안: 병목명 및 상황 해결·구조 개선·주의 사항 21개 문장 |
| 결과 ③ | 5개 전환 경로 × 4개 목표: 추천 2개와 순서, 총 20개 매핑 |
| 전체 조합 | 7 × 5 × 5 × 4 = 700개 |

수정한 원문 차이: Q2와 Q3의 축약 질문을 원문으로 복원하고, 생활 서비스의 예시를 ‘세탁소, 수리점, 청소, 자동차 관련 서비스’로 복원했다. 광고명·추천 순서·이유·운영 안내는 원문과 일치하여 변경하지 않았다. 기타 업종은 이전 확정대로 제외한다.

### 기능 통과와 구분해야 하는 분기 상태

- 오프라인 방문형의 유입·측정 부족: 오프라인 매장 문안만 표시.
- 온라인 구매형의 유입·측정 부족: 온라인 사이트 문안만 표시.
- 관심·전환·재구매 부족: 경로에 관계없이 각 문제의 공통 문안 표시. 상담·예약에 관한 전환 부족 안내도 원문대로 포함.
- 예약 방문형·상담 전환형·플랫폼 이동형의 유입·측정 부족: 온라인·오프라인 문안을 함께 표시하는 현재 임시 동작. 해당 168개 조합은 단일 분기 최종 확정으로 간주하지 않는다.
- 결과 ③의 상담 전환형을 포함한 20개 추천 매핑은 위 임시 분기와 별개로 모두 정의되어 있다.

전체 브라우저 검사 재현: `node scripts/verify-all-combinations.mjs http://127.0.0.1:5174`. 프로덕션 빌드를 먼저 준비하고 해당 주소에 미리보기 서버를 실행한다. 데스크톱 Chrome에서 실제 라디오 선택·다음·결과·다시 진단하기를 반복하며 화면의 원문 일치를 검사한다. 이 검사는 모바일 실기기 검사를 대체하지 않는다.

실행 결과: **700/700 통과**, 브라우저 런타임 오류 0개. 미선택 시 다음 버튼 비활성화, 단계별 선택지 수, 단일 선택, 결과의 정확한 문구·순서·선택 요약, 다시 진단 후 초기화를 전 조합에서 확인했다. 결과 로그: `artifacts/qa/all-combinations.json`. 별도 `verify-browser.mjs` 회귀 검사도 통과했다(모바일 에뮬레이션, 답변 복구, PNG/PDF 다운로드, 가이드 모달 포함).
